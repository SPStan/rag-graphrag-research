# RAG / GraphRAG — учебный исследовательский стенд

Сравниваем dense RAG, HippoRAG 2, RAPTOR и LightRAG по качеству ответов и расходу токенов, затем проверяем маршрутизацию между RAG и графом.

Для просмотра руководителем: [спецификация исследования](docs/SPEC.md), [статус задач по блокам](docs/TASKS.md), [результаты проверки стенда](docs/VERIFICATION.md).

Локальный [dense RAG MVP](docs/LOCAL_MVP.md) и baseline100 выполнены; MuSiQue reader закреплён на upstream HippoRAG commit. Baseline включает debug10 и не является независимой оценкой. На замороженном candidate S500[200:300] завершён Dense 3B run (`98d8b412-cec6-45e4-9c14-0e4ad85855bb`, EM=0,110, F1=0,186, recall@5=0,606). Попытка независимого HippoRAG index build (`e78eff08-532a-40b3-a359-49a6b08b32a7`) остановилась до QA: OpenIE gate выявил 160 неразрешённых исходов; граф сохранён только как диагностический. Поэтому парного сравнения на candidate view пока нет. Подробные безопасные агрегаты — в [сводке candidate view](results/summary/musique-independent-candidate-s500-200-299.json), решение и ограничения — в [ADR-0007](.adr/0007-openie-extraction-audit-and-independent-evaluation.md).

Подготовлены [данные и подвыборки](docs/DATA.md): MuSiQue и HotpotQA, по 500 вопросов и 5500 пассажей, seed 42. Источники, контрольные суммы и ID зафиксированы; все размеченные supporting-пассажи сохранены. Подготовка повторяется командами из docs/DATA.md.

Подробное исходное задание: [3_1_student_track_v1.md](3_1_student_track_v1.md). Маршрут совместной работы: [WORK_PLAN.md](WORK_PLAN.md). Числа из исходного обзора литературы не являются результатами этого репозитория.

Baseline100 на Qwen2.5 3B (`d49b37ad-51b1-42d9-8162-fe6424bfea84`) и парный replay на 7B (`48c2bb0e-9af4-4891-9224-69268ce8e4bf`) связаны с MLflow и Langfuse; использованы одни и те же top-5 контексты. ## Python-окружение

Проверенная платформа: Windows, Python 3.12.6, Docker Desktop с WSL 2. Все команды выполняются из корня клонированного репозитория.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.lock.txt
.\.venv\Scripts\python.exe -m pip check
```

Lock-файл получен через `pip freeze` на Windows и содержит `pywin32`. Восстановление на чистой машине и перенос на Linux пока не проверены; этот файл не является универсальным Linux lock-файлом.

## Запуск Langfuse из PowerShell

Docker Desktop должен быть открыт и показывать `Engine running`.

Перейди в папку клонированного проекта (путь ниже — пример):

```powershell
Set-Location -LiteralPath 'C:\projects\rag-graphrag-research'
```

При первом развёртывании создай файл настроек. Если `.env` уже существует, скрипт сохранит его без изменений:

```powershell
python scripts/setup_langfuse_env.py
```

Проверь конфигурацию без вывода паролей:

```powershell
docker compose config --quiet
```

Запусти сервисы:

```powershell
docker compose up -d
```

При первом запуске Docker скачает шесть образов. Длительность зависит от сети. После скачивания базам данных и Langfuse потребуется время на запуск и подготовку таблиц.

Проверь состояние:

```powershell
docker compose ps
```

Открой [локальный Langfuse](http://localhost:3000). Создай локальную учётную запись в интерфейсе; служебные пароли из `.env` для входа в веб-интерфейс не используются. Доступ к внутренней LLM для открытия интерфейса и отправки тестовой трассы не требуется.

Создай организацию, проект и API-ключи проекта. Добавь в существующий `.env` три переменные из `.env.example`: `LANGFUSE_PUBLIC_KEY`, `LANGFUSE_SECRET_KEY`, `LANGFUSE_BASE_URL=http://localhost:3000`. Служебные пароли сохраняй без изменения.

```powershell
.\.venv\Scripts\python.exe scripts\smoke_langfuse.py
```

Скрипт проверяет авторизацию, отправляет `smoke-test-no-llm` со span `local-python-step`, ожидает их появления через API и сохраняет JSON в `results/smoke/`. Успех: `status=verified`. Ссылка в JSON ведёт на локальный сервер автора прогона и не доступна руководителю через интернет.

## Запуск и проверка MLflow

В отдельном PowerShell из корня проекта:

```powershell
.\.venv\Scripts\mlflow.exe server --host 127.0.0.1 --port 5000
```

Оставь окно открытым. В другом окне из той же папки:

```powershell
.\.venv\Scripts\python.exe scripts\smoke_mlflow.py
```

В [MLflow](http://127.0.0.1:5000) открой ссылку на run из вывода команды. Эксперимент: `rag-graphrag-smoke`; имя запуска: `smoke-test-no-llm`; параметры: `mode=mock`, `llm_calls=0`, `retrieval_method=none`; метрика: `toy_score=1`. Каждый запуск скрипта создаёт новый run.

Проверенный запуск использует локальную `mlflow.db` в корне проекта. База и каталоги артефактов исключены из Git. MLflow пока не входит в Compose и запускается отдельно после перезагрузки; остановка — `Ctrl+C` в окне сервера. Сохранность артефактов проверена для локального HippoRAG debug10: JSONL, metrics и manifest были скачаны из MLflow и побайтно сверены с локальными файлами. Явная конфигурация удалённого хранилища остаётся отдельной задачей.

## Что запускается

| Сервис | Роль |
|---|---|
| langfuse-web | Веб-интерфейс и API Langfuse |
| langfuse-worker | Обработка поступивших событий |
| postgres | Пользователи, проекты и настройки |
| clickhouse | Трассы и аналитические данные |
| redis | Очередь задач |
| minio | Хранение файлов и поступивших событий |

На компьютере доступны только `127.0.0.1:3000` для Langfuse и `127.0.0.1:9090` для хранилища. Базы данных общаются внутри сети Compose. Подключение с другого компьютера потребует отдельной настройки.

## Логи и остановка

Если страница не открывается после запуска:

```powershell
docker compose ps -a
docker compose logs --tail 60 langfuse-web langfuse-worker
```

Если старый вариант `.env` выдаёт `403 Forbidden` для `cgr.dev` при загрузке MinIO по `@sha256`, значение `MINIO_IMAGE` должно быть `cgr.dev/chainguard/minio:latest`. Это исправление уже внесено в текущие `.env`, `.env.example` и скрипт подготовки. Остальные пароли и ключи сохраняются. Скачивание по тегу и запуск MinIO проверены на этом компьютере: контейнер получил статус `healthy`.

Остановить стенд:

```powershell
docker compose stop
```

Снова запустить:

```powershell
docker compose up -d
```

Данные сохраняются в именованных томах Docker. `docker compose down` удаляет контейнеры и сеть, сохраняя именованные тома. Флаг `-v` удаляет тома с данными — для обычной остановки он не нужен.

`.env` содержит случайные служебные пароли и ключ шифрования. Он исключён из Git; сохрани его вместе с резервной копией томов. Для существующих данных нельзя просто сгенерировать другой набор паролей и ключей. Не публикуй содержимое `.env` и полный вывод `docker compose config`; для проверки используй `--quiet`.

## Источник и воспроизводимость

За основу взят [официальный Compose Langfuse](https://langfuse.com/self-hosting/deployment/docker-compose). Исходный файл сохранён в `infra/langfuse/docker-compose.upstream.yaml`, его точная ревизия и URL — в `infra/langfuse/upstream.json`.

`infra/langfuse/images.lock.json` сохраняет SHA-256 идентификаторы образов. Пять образов запускаются по digest. Для MinIO сделано исключение: публичный `cgr.dev` вернул HTTP 403 при скачивании по digest, поэтому используется доступный тег `cgr.dev/chainguard/minio:latest` и `pull_policy: missing`. Уже скачанный образ используется повторно без обновления при обычном запуске. Digest фактически скачанного MinIO сохраняется в lock-файле, но сам тег изменяемый: на другой машине может скачаться другая сборка. Перед фиксацией исследовательского окружения сохраним используемый образ в архив через `docker image save` или в собственный доступный реестр.

Локальная адаптация: явное имя проекта `rag-graphrag`, случайные обязательные секреты, доступ через localhost, постоянные тома, авторизованная проверка Redis, увеличенный запас времени для первого запуска баз и отключённая телеметрия Langfuse. Ненужные для первого этапа интеграции не включены.

## Организация работы

Один репозиторий содержит код стенда и последующее исследование. Каждый завершённый шаг фиксируется отдельным содержательным коммитом; по заданию история пополняется каждую неделю. Начальная фиксация содержит уже выполненную настройку. Даты и история прошлой работы не реконструируются задним числом.

Проверяемые результаты, критерии готовности и зависимости блоков ведутся в [docs/TASKS.md](docs/TASKS.md). В Git попадают код, спецификации, конфигурации без секретов, ID подвыборок и небольшие проверенные результаты. Сырые данные, индексы, окружения, базы и секреты остаются локально. `git commit` сохраняет версию локально, `git push` передаёт коммиты в удалённый репозиторий.
