# Итог вехи E1–E5 и демонстрация

**Вопрос исследования.** Улучшают ли HippoRAG2 и RAPTOR ответы на многошаговые
вопросы по сравнению с Dense при одинаковом reader? Сколько токенов стоит
это различие и есть ли основание выбирать метод для отдельного вопроса?

HippoRAG2 дал лучший средний F1 на двух S500, но потребовал больше LLM-токенов.
Dense всё ещё решал часть вопросов, на которых ошибался HippoRAG2. Этот резерв
виден у oracle, а единственный проверенный сигнал Dense не показал устойчивого
результата на двух наборах. Оснований запускать общий каскад E6 пока нет.

Для блока «аналоги → открытый вопрос» есть [таблица на один слайд](related-work-comparison.md#slide-version)
из [issue25](https://github.com/SPStan/rag-graphrag-research/issues/25).
Это обзор методов из литературы. Ниже приведены измерения проекта.

## Условия сравнения

MuSiQue и HotpotQA, по 5 500 исходных пассажей и 500 одинаковых вопросов для
каждого метода внутри датасета. Dense ищет близкие по cosine similarity пассажи.
HippoRAG2 использует граф сущностей и фактов, fact filter и ранжирование
исходных пассажей. RAPTOR ищет по дереву, где выдача может включать
суммаризации. Общий reader `iairlab/qwen3.8-27b` получает до пяти элементов
выдачи, даёт один ответ, temperature 0, seed 42, предел 512 выходных токенов.
Эмбеддинги BGE-M3 локальные. EM и token F1 оценивают этот один ответ.
Passage recall@5 относится к поиску. Покрытие источников через узлы RAPTOR
показано отдельно. Условия и SHA закреплены в [плане S500](../results/summary/full-experiment.json).

## E4. Стоимость запроса и точного ответа

| Датасет | Dense LLM-токенов/запрос | HippoRAG2 | RAPTOR |
|---|---:|---:|---:|
| MuSiQue | 1 504,5 | 4 679,7 | 3 917,2 |
| HotpotQA | 1 398,4 | 4 532,9 | 3 238,7 |

`I` — самостоятельная индексация, `q` — средний логический расход запроса
на все предложенные случаи, включая сбои и fact filter. Из этого
`T(N)=I+Nq`, `C(N)=I/N+q`. Деление `C(N)/EM` даёт стоимость на точный ответ
при допущении постоянного EM, выраженного долей. При EM=0 величина не
определена. LLM и BGE считаются отдельно. При неполном учёте показан известный
минимум. По LLM-токенам нижние границы HippoRAG2 и RAPTOR уже превышают
стоимость Dense в расчёте на запрос и на точный ответ. Это токенная оценка,
денежные цены не измерялись.

Пример для устного объяснения — на 1 000 запросов MuSiQue индексация Dense
требовала ноль LLM-токенов. Из среднего `q≈1 504,5` следует около 1,50 млн
LLM-токенов. При EM 34,8% ожидается около 348 точных ответов и около 4 323
LLM-токенов на точный ответ. BGE здесь учитывается отдельно.

Источники — те же run ID E1–E3, атрибуция в [E4 JSON](../results/summary/e4-cost.json).
[48 строк для N=100, 1 000, 10 000 и 100 000](../results/summary/e4-cost.md),
[график](../results/summary/e4-cost.svg), [PR41](https://github.com/SPStan/rag-graphrag-research/pull/41).
Команда E4 ниже.

## Oracle и E5. Резерв выбора и проверка сигнала

| Датасет | Oracle EM, % | Oracle F1, % | Рост F1 к Hippo, п.п. | Только Dense точен |
|---|---:|---:|---:|---:|
| MuSiQue | 47,20 | 58,16 | 4,61 | 19 из 500 |
| HotpotQA | 69,00 | 79,76 | 2,06 | 12 из 500 |

Oracle берёт для каждого вопроса максимум двух готовых оценок и усредняет
по вопросам. Для EM и F1 максимумы считаются независимо. Чтобы выбрать
лучший ответ, oracle пользуется уже известной оценкой. Получается верхняя
граница для выбора между сохранёнными ответами. Источники — те же E2 run ID
и проверенный ledger E3, [таблица oracle](../results/summary/oracle.md) из
[PR42](https://github.com/SPStan/rag-graphrag-research/pull/42). Команда oracle ниже.

| Датасет | Проверено | Ошибки Dense / точные | ROC-AUC | Время сигнала, мкс/вопрос |
|---|---:|---:|---:|---:|
| MuSiQue | 100 | 59 / 41 | 0,585 | 2,806 |
| HotpotQA | 100 | 37 / 63 | 0,441 | 2,927 |

Сигнал — минус cosine similarity первого Dense passage. Формула и знак
зафиксированы на tuning до этой проверки в `41c2f1c`. ROC-AUC показывает,
как часто сигнал ставит ошибку Dense выше точного ответа, с половиной веса
при равенстве. EM=0 вычисляется при оценивании, отдельно от сигнала.
Время измерено только для вычисления и валидации признака. Дополнительные
LLM- и BGE-токены и POST равны нулю. ROC-AUC выше 0,5 только на MuSiQue,
гипотеза для обоих датасетов не подтвердилась. Источники — [run IDs и freeze](DENSE_ERROR_SIGNAL.md#результат-фиксированной-проверки),
[отчёт E5](../results/summary/dense-error-signal.md) из
[PR43](https://github.com/SPStan/rag-graphrag-research/pull/43). Команда E5 ниже.

## Воспроизведение из корня репозитория

Нужен Python 3.12 и окружение из `uv.lock`. В первой строке после установки
выберите новый каталог результатов в `.cache`. На машине Елисея источники
сохранены в указанных ниже каталогах. Для другого компьютера нужно получить
от владельца локальную копию E1 индексов, терминальных манифестов и журналов,
E2 plans/cases/response/checkpoints/journals со всей родительской цепочкой,
private ledger E3 и файлы `data/processed/<dataset>/labels.json` и
`data/ids/<dataset>_s500.json`. Часть планов и проверок содержит абсолютные
ссылки. Для точного повтора нужен исходный layout либо запуск на машине
Елисея. GitHub достаточно для E4 и чтения опубликованных агрегатов.

```powershell
$env:UV_PROJECT_ENVIRONMENT = '.venv-check'
uv sync --locked
$py = (Resolve-Path .venv-check/Scripts/python.exe).Path
$out = Join-Path $PWD ".cache/milestone22-$(Get-Date -Format yyyyMMdd-HHmmss)"
$e1 = 'C:/Users/Elisei/.codex/worktrees/dense-target-smoke/Rag, GraphRAG'
$e2 = 'C:/Users/Elisei/.codex/worktrees/e2-shared-evaluation/Rag, GraphRAG'
$data = 'C:/Users/Elisei/Documents/ChatGPT/Rag, GraphRAG'

# E1. Шесть индексов и новый отчёт
& $py -m scripts.reproduce_e1_summary --artifact-root $e1 --plan .cache/e1-hotpot-local-recovery2-plan.json --output-dir "$out/e1"

# E2 и E3. Терминальные случаи, журналы и парные интервалы
& $py -m scripts.e3_evaluation --artifact-root $e2 --data-root $data --output "$out/e3"

# E4. Таблица стоимости и CSV
& $py -m scripts.e4_cost --output "$out/e4-cost"

# Oracle. Сверка пересчитанных оценок с закрытым ledger
& $py -m scripts.analyze_oracle --artifact-root $e2 --data-root $data --ledger "$e2/.cache/e3-oracle-inputs-private.json" --output "$out/oracle.json"
```

Выполняйте команды по очереди и остановитесь при ненулевом коде выхода.
E5 воспроизводится из исходного кода freeze в отдельном checkout.
CSV остаётся внутри приватной `.cache` каталога E2. Для E5 при каждом запуске
выбирается новое имя CSV. Остальные отчёты записываются в `$out`.

```powershell
$freeze = '41c2f1c6d44b98609be79f6c4986271f0e54d1e1'
$frozenTree = "$out/e5-source"
$privateCsv = "$e2/.cache/$(Split-Path $out -Leaf)-private.csv"
git worktree add --detach $frozenTree $freeze
if ($LASTEXITCODE -ne 0) { throw 'Frozen checkout unavailable' }
Push-Location $frozenTree
try {
    git diff --exit-code $freeze -- scripts/run_dense.py
    if ($LASTEXITCODE -ne 0) { throw 'Frozen dependency changed' }
    & $py -m scripts.dense_error_signal evaluate --artifact-root $e2 --data-root $data --decision results/summary/dense-error-signal-freeze.json --freeze-commit $freeze --private-output $privateCsv --output "$out/e5.json"
    if ($LASTEXITCODE -ne 0) { throw 'E5 replay failed' }
} finally { Pop-Location }
& $py -m scripts.verify_milestone_tables --replay-dir $out
```

У E5 фактическое время повторного расчёта меняется. Для проверки чисел
сравниваются аналитический digest и SHA приватного CSV. У E3 путь к private
файлам и метаданные окружения могут отличаться, поэтому сверяются таблицы и
digest оценок. Сводки и выводы остаются доступны без private файлов.

Локальная проверка из рабочего дерева issue22 прошла. E1 проверил 6 индексов
и воспроизвёл Markdown побайтно. E2-сводки прошли сверку оценок и журналов
через E3, а их SHA совпали с опубликованными. Совпали таблицы E3, все 48 строк
проекций E4 и таблицы oracle. Для E5 совпали аналитический digest и SHA CSV.
График E4 в этом повторе отдельно не рендерился. Модельных запросов не было.

## Сценарий защиты

Порядок показа на 5–7 минут. Сначала слайд аналогов и общие условия. Затем
одна строка из E1, таблица качества E2/E3 и два заранее выбранных примера
из [разбора E3](E3_EVALUATION.md). На локальной машине откройте соответствующие
сохранённые строки `evaluation.json` из папок
`results/raw/e2-musique-s500-unattempted-v1` и
`results/raw/e2-hotpotqa-s500-unattempted-v1` под `$e2`.
Выведите по каждому методу заголовки найденных фрагментов, ответ и EM/F1.
Команда проверена локально и возвращает шесть строк, по три метода на пример.
Для показа вне локальной машины используйте опубликованные агрегаты и описания
этих tuning-примеров. Закрытые тексты, контрольные оценки и CSV остаются локально.

```powershell
$examples = @(
    @{ Run = 'e2-musique-s500-unattempted-v1'; Id = '2hop__126306_396277' }
    @{ Run = 'e2-hotpotqa-s500-unattempted-v1'; Id = '5adc6f6255429947ff173961' }
)
foreach ($case in $examples) {
    $saved = Get-Content -LiteralPath "$e2/results/raw/$($case.Run)/evaluation.json" -Raw | ConvertFrom-Json
    $saved.question_results | Where-Object question_id -eq $case.Id |
        Select-Object method, question, answer,
            @{Name='RetrievedTitles'; Expression={$_.retrieval.passages.title -join ' | '}},
            @{Name='EM'; Expression={$_.metrics.em}},
            @{Name='F1'; Expression={$_.metrics.f1}},
            @{Name='RecallAt5'; Expression={$_.metrics.passage_recall_at_5}},
            @{Name='Provenance'; Expression={$_.metrics.supporting_provenance_coverage}}
}
```

- **MuSiQue.** Dense и RAPTOR назвали другое произведение, HippoRAG2 ответил
  точно. Dense нашёл половину опорных пассажей, HippoRAG2 — все. На показе
  отметьте, какой фрагмент связывает вопрос с нужным произведением.
  Различие согласуется с нехваткой контекста, причинность этот пример не доказывает.
- **HotpotQA.** При полном passage recall Dense выбрал противоположный
  вариант сравнения. HippoRAG2 и RAPTOR ответили точно. Покажите, что наличие
  нужных пассажей и умение сопоставить изложенные в них факты проверяются отдельно.

Затем объясните своими словами `I`, `q`, `C(N)/EM` и верхнюю границу oracle.
Вопросы для самопроверки. Как учитывается сбой? Почему ноль в ДИ не доказывает
равенство? Почему ROC-AUC ошибки Dense не показывает, исправит ли её HippoRAG2?

Показ студентом и замечания куратора пока ожидаются. После показа записать
дату, фактические активные часы студента, заданные вопросы, ответы и открытые
замечания. Оценка задачи 3 часа из issue — план, фактическое время студента
не измерялось. Локальный пересчёт выполняется автоматически и учитывается отдельно.

## Решение для следующего этапа E6

HippoRAG2 остаётся заранее выбранным графовым методом. Текущий признак
`−top1 cosine` сохраняется как проверенный кандидат с отрицательным общим
результатом. До отдельного решения куратора не назначать новый порог или
сигнал по историческому control и не запускать каскад.

Предложение для обсуждения. Либо закрыть этап с отрицательным результатом,
либо согласовать отдельную проверку с защищённой выборкой и заранее фиксированным
порогом. В E6 отдельно проверить парное качество и токены при одинаковых
вопросах, сравнить с always-Dense, always-Hippo и простым смешиванием при
сопоставимом расходе. Учитывать стоимость уже выполненного Dense, сигнала,
эскалации, fact filter, BGE и сбоев. Любые новые вызовы требуют отдельного
утверждённого лимита и условий остановки при неизвестном usage. Бюджеты
прошлых прогонов относятся к своим протоколам.
