# Целевой API: ограниченная проверка issue #8

Статус на 6 октября 2026: **блокер удалённой генерации**. Один разрешённый запрос к Qwen завершился ответом API, но текст отсутствовал в ожидаемом `choices[0].message.content`. Повторный запрос в рамках этой проверки не выполнялся. Локальные эмбеддинги BGE-M3 проверены. Это проверка интерфейса, не benchmark качества.

## Подтверждённые условия и границы

Куратор сообщил: адрес `https://api.duckduck.cloud/v1`, модель `iairlab/qwen3.8-27b`, локальный BGE-M3 вместо удалённой модели эмбеддингов. Контекст Qwen3.8 — 262k токенов по сообщению куратора; в этом smoke предел не измерялся. Он также сообщил о поддержке JSON mode/JSON Schema и `enable_thinking: false`, закреплённых именах моделей и снятии прежнего административного лимита 90 млн токенов. Точную ревизию backend, применение параметра и устойчивость под параллельной нагрузкой эта проверка не установила. Протокольный предел issue #8 — 50 000 учтённых токенов — сохраняется.

Для OpenAI-совместимого HTTP-запроса `enable_thinking` передаётся полем верхнего уровня. [Документация QwenCloud](https://docs.qwencloud.com/api-reference/chat/openai-chat) описывает тот же параметр; конкретная настройка лабораторного LiteLLM пока подтверждена только сообщением куратора.

## Повторение

Локально в игнорируемом Git файле `.env.target-api` указать:

```text
TARGET_API_BASE_URL=https://api.duckduck.cloud/v1
TARGET_API_MODEL=iairlab/qwen3.8-27b
LITELLM_API_KEY=<ключ из закрытого канала>
OLLAMA_EMBED_MODEL=bge-m3:latest
```

Запустить Ollama с уже установленным BGE-M3. Для чистой рабочей копии сначала создать проверочное окружение по `AGENTS.md` (`UV_PROJECT_ENVIRONMENT=.venv-check`, затем `uv sync --locked`). Из корня рабочей копии:

```powershell
.\.venv-check\Scripts\python.exe scripts\check_target_api.py
```

Скрипт читает настройки из окружения и `.env.target-api` в текущей папке. Он заранее отклоняет отсутствующие настройки и существующий итоговый файл. После проверки локальной модели выполняет **один** пакетный запрос эмбеддингов и, при наличии его usage, **один** запрос генерации без повторов. `max_tokens=32`, `enable_thinking=false`, явный timeout. Отчёт: `results/summary/target-api-check.json`. Для нового разрешённого запуска требуется отдельное имя `--output`; текущий результат сохраняется как свидетельство первой попытки. Ключ и заголовки авторизации в отчёт не попадают.

## Полученный результат

| Часть | Результат | Учёт |
|---|---|---|
| Локальный BGE-M3 | 2 из 2 векторов, размерность 1024, digest `79076464…2146bab`, 5,64 с | 19 локальных prompt tokens |
| Удалённая Qwen3.8 | 1 запрос, текстового `message.content` не получено; `remote_answer_missing` | Неизвестен: ответ не сохранён после ошибки проверки |
| `GET /user/daily/activity` | Не проверялся: схема и права доступа не подтверждены | Суточную статистику нельзя приписать одному запросу |

Без текстового ответа и надёжно сохранённого per-response usage готовность целевой генерации **не подтверждена**. Нужно уточнить у куратора, может ли ответ при `max_tokens=32` и `enable_thinking=false` приходить без `message.content`, и какой безопасный способ получить метаданные ответа и расход. После уточнения — отдельная ограниченная проверка. JSON mode и JSON Schema здесь не тестировались. Полные данные датасетов, индексы и локальные эксперименты не затрагивались.
