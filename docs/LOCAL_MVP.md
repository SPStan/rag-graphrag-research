План от 23 сентября 2026 с учётом обратной связи руководителя. Цель: вопрос → top-5 пассажей → ответ настоящей локальной модели → оценка → сохранённый результат. Внутренний API не блокирует этот этап.

## Manifest и embeddings без усечения

Новые запуски сначала записывают JSON-манифест со статусом, ожидаемыми ID, SHA256 подготовленных данных, model digests, Ollama/Python/runtime, Git commit и dirty-флагом, хэшами файлов кода, хэшем шаблона и параметрами. При завершении он получает итоговый статус и хэш JSONL; при сбое — тип и текст ошибки и имя частичного результата. Старые JSONL остаются неизменными и не имеют такого манифеста.

В новых embedding-запросах явно используется `truncate=false`. Старый кэш `indexes/dense/<dataset>-bge-m3.npz` не содержит этой настройки, поэтому он сохраняется как есть. Отдельный `*-notrunc-v2.npz` уже построен и проверен для 5500 пассажей MuSiQue; дальнейшие MuSiQue запуски используют этот кэш. Кэш не считается совместимым с другим набором данных или digest модели.

Исходная стоимость этого no-trunc кэша подтверждена manifest запуска `ed95bea9-9d11-4234-a80f-46ba3a8fd127`: полный корпус из 5500 пассажей был встроен за 78,764 с. При повторном использовании кэша время его чтения хранится отдельно; оценщик также показывает ID и время первоначальной сборки. В исходном запуске счётчики токенов и серверные длительности embedding API не сохранялись, поэтому они остаются `null` (неизвестно), а не восстанавливаются приблизительно. Runner проверяет завершённость источника и SHA256 его JSONL перед тем, как записать локальный sidecar provenance с контрольной суммой кэша.

Reader `hipporag2-musique-one-shot-v5` закреплён на upstream commit `1438aba3fc44ff10573e5a5e1e7cc3c7f9794aff`; источник и MIT attribution записаны в [THIRD_PARTY_NOTICES.md](../THIRD_PARTY_NOTICES.md). В сообщениях сохранены фиксированный few-shot пример и роли system/user/assistant/user. Runner намеренно принимает только MuSiQue: шаблон для HotpotQA пока не выбран и не проверен. Генерация использует `temperature=0`, `seed=42`, `num_predict=512`, `num_ctx=4096`; seed снижает один источник вариативности, но не гарантирует полную детерминированность. Модель не получает ответ или supporting IDs. JSONL сохраняет сырой вывод и отдельно извлечённый финальный ответ; отсутствующая или неоднозначная метка означает пустой ответ, который остаётся в знаменателе и получает нулые EM/F1.

Оценщик привязывает оценку к `expected_question_ids` manifest, проверяет его статус, run ID и SHA JSONL. Он отклоняет неполный/смешанный прогон, неполную generation response и отсутствующую конфигурацию; `recall@k` ограничен первыми k пассажами. Runner сохраняет ответ и статус в частичный `.part` файл, затем выставляет `status=failed`, если Ollama не сообщил `done=true` и непустой `done_reason`; такой файл оценщик не принимает как полный. Формулы нормализации и F1 сверены с HippoRAG/SQuAD; версия оценщика записывается в метриках. Для старых запусков без manifest остаётся явный `--expected-view`; старые JSONL и оценки не переписываются автоматически.

## Экспорт завершённого Dense RAG запуска

`scripts/track_dense.py` связывает завершённые JSONL, metrics и manifest по общему `run_id`, восстанавливает полный текст top-k пассажей из закреплённого корпуса, отправляет параметры/метрики/артефакты и trace со стадиями query embedding, retrieval и generation в локальные MLflow и Langfuse. Запись помечена как post-hoc экспорт: измеренные интервалы берутся из исходного прогона, а не из времени отправки trace. Локальные токены Ollama помечаются как usage, не как счёт за API. Перед запуском должны быть доступны локальные сервисы и `.env`; ключи не выводятся и экспорт Langfuse разрешён только на localhost. Экспорт run `06dcabef-de41-4815-a5ac-4bcb3eb01b11` проверен: MLflow run `5ee46c6f61cb43ef9d082f7accfc4676` имеет статус FINISHED, метрики EM/F1/recall@5 и три скачиваемых артефакта; JSONL после скачивания совпал с SHA из manifest. MLflow trace содержит root и четыре типа дочерних span с входами/выходами. Langfuse trace `f1a4fc02941fa8d6cda110e3187abf78` содержит общий `run_id`, пять полных retrieval-пассажей и usage генерации 1178 входных/158 выходных токенов. После `docker compose restart` Langfuse trace сохранился; после перезапуска MLflow server run, trace и артефакты читались, SHA JSONL совпал с manifest. Первая попытка экспорта прервалась из-за кодировки emoji в Windows-консоли; незавершённая запись оставлена со статусом FAILED, итоговый экспорт — отдельный завершённый run.

## Первый Dense RAG прогон

Из корня проекта запусти локальный PoC на первых 10 закреплённых вопросах MuSiQue:

```powershell
.\.venv\Scripts\python.exe scripts\run_dense.py --dataset musique --limit 10
```

Скрипт создаёт или использует локальный кэш эмбеддингов для общего корпуса из 5500 пассажей, получает top-5 для каждого вопроса через Ollama и передаёт reader только найденные пассажи и вопрос. Reader использует закреплённый в коде one-shot шаблон MuSiQue HippoRAG 2 с ролями system/user/assistant/user и завершением `Answer:`; сырой вывод хранится отдельно от извлечённого ответа. Текущая версия `hipporag2-musique-one-shot-v5` поддерживает только MuSiQue. Upstream-файл и commit закреплены в [THIRD_PARTY_NOTICES.md](../THIRD_PARTY_NOTICES.md). В JSONL записываются ID, cosine scores, длительность, локальные счётчики токенов, параметры, версия и SHA256 сообщений reader. `labels.json` скрипт не читает. Первый запуск может занять несколько минут из-за эмбеддинга корпуса; кэш `indexes/dense/` и JSONL в `results/raw/` исключены из Git.

Результат помечается `mode=local-poc`; число локальных токенов не является расходом внутреннего API. Сам прогон не читает эталонные ответы и не считает качество.

После завершения генерации можно отдельно посчитать метрики:

```powershell
$runFile = Read-Host "Вставь путь JSONL из строки Results"
.\.venv\Scripts\python.exe scripts\evaluate_dense.py $runFile --expected-view debug10
```

Оценщик запускается только после генерации и читает `labels.json` отдельно: для ответа берётся максимум по эталону и алиасам, EM и token F1 используют нормализацию HippoRAG/SQuAD, recall@k — доля supporting IDs, найденных среди первых k результатов. Для новых запусков paired manifest задаёт полный упорядоченный список ID; оценщик проверяет статус, run ID и SHA JSONL и отклоняет неполный прогон или несогласованную конфигурацию. Пустой ответ (например, если маркер `Answer:` отсутствует или неоднозначен) получает ноль и остаётся в знаменателе. Для исторического JSONL без manifest укажи закреплённый view, например `--expected-view debug10`. Метрики сохраняются рядом с JSONL с суффиксом `.metrics.json`. Эталон и supporting IDs не передаются reader-модели.

На весь этап предварительно 20–30 часов активной работы. Скачивание, установка GPU-зависимостей и скорость генерации могут увеличить срок. При пяти часах в день: два рабочих блока примерно по два часа и час на понимание и документирование. Не ставить отметки о готовности по календарю.

## Данные и условия

Основная подвыборка — 500 вопросов на датасет. Существующие debug10, debug20, baseline100 и pilot200 остаются префиксами одного списка: все сохранённые локальные прогоны использовали только 10 вопросов debug10, и эти ID входят в baseline100. Поэтому baseline100 пригоден как инженерный smoke, но не как независимая оценка. Отдельный `holdout100` закреплён за индексами 400–499 и не пересекается с первыми 200 ID; запуск на нём не выполнялся. Поиск при оценке ведётся по общему зафиксированному корпусу, а не только по supporting-пассажам выбранного вопроса.

Сохраняем supporting-пассажи всех 500 вопросов и добавляем дистракторы до 5500. Если supporting-пассажей больше целевого размера, сообщаем это и пересматриваем размер явно. В Git — ID, код, тесты и небольшие сводки; сырые данные и индексы остаются локально. Перед публикацией производных материалов проверяются условия источника.

## Модели и ресурсы

Приоритет для эмбеддера — bge-m3 из задания. Кандидат для первого генератора — небольшой квантованный Qwen; Qwen2.5 3B Q4_K_M через Ollama рассматривается как стартовый вариант, а не утверждённый по измерениям выбор. Источники: [bge-m3](https://huggingface.co/BAAI/bge-m3), [сборка Qwen](https://ollama.com/library/qwen2.5:3b).

Проверяем версии и совместимость до установки. Размер файла модели не равен требуемой VRAM. Начинаем с одного запроса и малого batch. При необходимости сначала считаем и сохраняем embeddings документов/вопросов, выгружаем эмбеддер, затем запускаем генератор. Фиксируем фактический GPU/CPU режим, truncation, контекст и ограничения. Не меняем embedding-модель молча.

## Результаты и проверки

- Различаем mock, local-poc и основной benchmark; toy_score не переносится в научные таблицы.
- На вопрос сохраняются ID, retrieved IDs, предсказание, эталон для оценки, время, статус/ошибка, модель, настройки, токены и run_id. Ошибочные вопросы не исключаются молча из знаменателя.
- Счётчики токенов берём из реального ответа сервера; если недоступны, значение неизвестно, а оценка токенизатором явно помечается оценкой.
- Метрики проверяем на примерах с известным результатом. Seed генерации не объявляем гарантией полной GPU-детерминированности.
- Langfuse хранит трассу вопроса, MLflow — настройки/метрики/артефакты запуска, JSONL — подробные исходы. Общий run_id связывает записи.
- Проверяем чтение файла-артефакта MLflow и доступность прежних результатов после перезапуска. Перенос MLflow в Compose не является условием MVP.
- Низкий F1 не мешает завершению технического MVP, если подсчёт корректен и ограничения объяснены.

## После MVP

HippoRAG 2 на sample, затем RAPTOR на малом корпусе; LightRAG — расширение. Используем готовые пакеты/сервисы, добавляя необходимые адаптеры и оценку. Сравнения выполняются на одинаковых данных и моделях; несовместимости и ограничения маленького генератора сохраняются в отчёте.

Доску задач подключаем после её появления, до этого статус ведётся в docs/TASKS.md и PR. При готовности к ревью студент отправляет ссылку руководителю. Руководитель разрешил напоминать ему о ревью; автоматические сообщения и напоминания этим планом не создаются.
