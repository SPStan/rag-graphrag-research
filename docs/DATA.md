# Данные локального MVP

Источник — подготовленные авторами HippoRAG 2 наборы [osunlp/HippoRAG_2](https://huggingface.co/datasets/osunlp/HippoRAG_2), ревизия `5ec05b38deecc3318bb432c69865959c56058990`. Старое имя `osunlp/HippoRAG_v2` перенаправляется на этот репозиторий. Размеры и SHA-256 всех шести файлов — в [sources.lock.json](../data/sources.lock.json).

## Повторить подготовку

Из корня проекта, Python 3.12 (дополнительных библиотек не требуется):

```powershell
.\.venv\Scripts\python.exe scripts/download_data.py
.\.venv\Scripts\python.exe data/make_subsample.py
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Повторная загрузка проверяет локальные файлы без сетевого запроса. Повторная подготовка сверяет результат и сохраняет одинаковые байты. Повреждённые исходники и отличающийся результат дают ошибку, а не скрытое обновление. Для новой версии протокола используем новые каталоги через `--output-dir`, `--ids-dir` и `--report`; прежние результаты не удаляем.

## Протокол issue #7: назначение ID и проверка истории

Исходные S500 и `pilot200` остаются байт-в-байт прежними. [ADR-0015](../.adr/0015-pinned-comparison-and-signal-split.md) фиксирует отдельное разбиение для оценки сигнала задачи #21: позиции `S500[0:300]` для настройки (300 ID), `S500[300:400]` для однократной проверки (100 ID), `S500[400:500]` как прежний резерв (100 ID). Файлы [MuSiQue](../data/ids/musique_comparison_split.json) и [HotpotQA](../data/ids/hotpotqa_comparison_split.json) содержат точные списки, seed, ревизию и SHA исходных S500. Пилотные 200 ID входят в часть настройки; выбор сигнала, формулы, направления или порога по проверочной части запрещён. Даже после полного запуска S500 результаты 500 вопросов — описательная таблица, а не один независимый test set.

[Компактный аудит](../results/summary/question-usage-audit.json) связывает run ID с нулевыми позициями ID в опубликованных S500; для каждого run отдельно указаны **planned** из manifest и **observed** из raw JSONL, имена файлов и SHA-256. Ответы/вопросы в отчёт не попадают. Опубликованные summaries сверены по SHA, но не считаются доказательством выполнения отдельных ID без raw. В доступных локальных файлах наблюдались 200 уникальных MuSiQue ID: первые 100 и позиции 200–299; HotpotQA observed=0. В обоих наборах позиции 300–399 отсутствуют в найденных planned и observed. Проверка точных ID из этих позиций в tracked docs не дала совпадений. Это ограниченный аудит локальных артефактов и документации; личный просмотр вне них исключить нельзя. Прежний файл `musique_independent100_candidate.json` фиксирует **исторический** статус до запуска, но теперь его 100 ID уже использованы для диагностического сравнения.

Повторить сверку локальных журналов без модельных вызовов из рабочей папки с `results/raw`:

```powershell
python scripts/freeze_comparison_protocol.py --verify-only
```

В чистом checkout без private raw проверить опубликованные ID и границы:

```powershell
python scripts/freeze_comparison_protocol.py --verify-only --splits-only
```

Если появятся новые локальные результаты, полный аудит надо обновить отдельным проверяемым изменением; различие audit SHA в этой команде будет сигналом к пересмотру. Отсутствие файла не означает нулевого расхода или абсолютной нетронутости.

Агрегированный отчёт и контрольные суммы результатов: [results/data/subsamples.json](../results/data/subsamples.json). Решения о форматах и нормализации: [ADR-0002](../.adr/0002-pinned-data-and-passage-identity.md).

## Кандидат для независимой локальной оценки

Файл [musique_independent100_candidate.json](../data/ids/musique_independent100_candidate.json) фиксирует `S500[200:300]` и SHA-256 упорядоченного списка ID `a026de236266ceb4ee7faa4cde5d031996ecfd74f4e6edd806a8b08cc493d42b`. Он содержит только ID и контрольные суммы, не вопросы или labels. На дату фиксации проведена read-only сверка с 29 MuSiQue manifests и 4 raw JSONL без manifests: пересечений не найдено. Источник — revision `5ec05b38deecc3318bb432c69865959c56058990`; контрольная сумма labels сохранена в файле view. **С тех пор эта выборка была выполнена и разобрана** в локальном сравнении 26 сентября; статус `frozen_candidate_not_run` внутри исторического файла относится только к моменту создания и не отражает текущее использование. Команда ниже теперь ожидаемо обнаружит пересечение:

```powershell
.\.venv\Scripts\python.exe scripts\freeze_eval_view.py --verify-only --output data\ids\musique_independent100_candidate.json
```

Проверка не изменяет замороженный view и завершится ошибкой при пересечении с manifests или raw results. Для актуальной классификации используй аудит выше.

Проверка 23 сентября: 15 тестов прошли, включая 2 интеграционных теста на реальных данных. Повторная подготовка дала идентичные результаты. Без скачанных исходников интеграционные тесты пропускаются; остальные 13 не требуют сети. Для JSON в Git закреплены окончания строк LF, чтобы контрольные суммы манифестов не менялись при клонировании на Windows.

## Что означают файлы

- `data/raw/`: шесть исходных JSON, около 43 МБ, только локально.
- `data/processed/<dataset>/queries.json`: ID и вопрос. Это вход генерационного пайплайна.
- `data/processed/<dataset>/corpus.json`: общий корпус, ID/title/text; он доступен поиску.
- `data/processed/<dataset>/labels.json`: правильный ответ, допустимые алиасы и supporting IDs; только для оценки.
- `data/ids/`: публикуемые ID и происхождение выборки, без вопросов и текстов.

`labels.json` нельзя подмешивать в промпт модели. Поле idx в исходных данных не считаем глобальным идентификатором. Для MuSiQue сопоставляем paragraph_text, для HotpotQA собираем текст из предложений context. Совпадение проверяется по заголовку и полному тексту после нормализации пробелов. Обнаружен и объединён один канонический дубликат MuSiQue.

## Один понятный пример

В исходном `musique.json` первый вопрос имеет ID `2hop__13548_13529`: нужно определить, когда «Барселона» подписала футболиста, с которым сравнивали голы Месси в Кубке Испании. Один подтверждающий пассаж связывает сравнение с Марадоной, другой содержит дату его перехода. Эталон — июнь 1982 года. Поиск должен найти оба факта, а reader — соединить их. Это разбор источника, не результат работы модели и не обещание, что вопрос включён в первую сотню.

Наличие всех размеченных документов проверено автоматически, смысловую корректность всех 1000 аннотаций мы не проверяли. Ошибки исходника при анализе результатов нужно фиксировать, а не исправлять незаметно.

## Происхождение и условия данных

- MuSiQue: StonyBrookNLP, [исходный проект](https://github.com/StonyBrookNLP/musique), [лицензия CC BY 4.0](https://github.com/StonyBrookNLP/musique/blob/main/LICENSE).
- HotpotQA: Yang, Qi, Zhang et al., [страница набора и цитирование](https://hotpotqa.github.io/); авторы указывают CC BY-SA 4.0 для набора и обработанной Wikipedia.
- 2WikiMultiHopQA скачан как резерв исходного плана. Перед использованием и публикацией производных материалов отдельно проверим условия исходного набора и текстов; лицензия кода не приравнивается автоматически к лицензии всех данных.
- Использована упаковка HippoRAG 2; исходная HF-карточка указывает язык en, но не предоставляет единую лицензию на все объединённые наборы.

В этот репозиторий не включаются полные корпуса или преобразованные тексты. Ссылки на создателей сохраняются; ограничения исходных данных не изменяются этим проектом.
