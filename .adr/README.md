# Журнал архитектурных решений

ADR (Architecture Decision Record) объясняет, почему выбран конкретный вариант и какие альтернативы были рассмотрены. Журнал ведётся с 23 сентября 2026 по просьбе руководителя.

| Запись | Статус | Решение |
|---|---|---|
| [0001](0001-local-mvp-and-agent-artifacts.md) | Принято | Локальный MVP до внутреннего API; инструкции агента и ADR в основном репозитории |

Новая запись получает следующий номер и фактическую дату. Шаблон: [template.md](template.md). Статусы: предложено, принято, отклонено, заменено. Принятое решение может требовать проверки реализации: это указывается отдельно.

При смене решения добавляем новую запись со ссылкой на предыдущую, а прежнюю помечаем заменённой. Не переписываем прошлую аргументацию так, будто новый выбор был известен заранее. Для старой настройки допустима отдельная ретроспективная запись с указанием источников и неизвестных причин.

Не каждый небольшой рефакторинг требует ADR. Записываем выбор модели/рантайма, протокол данных, формат результатов, учёт стоимости, границы компонентов и существенные изменения воспроизводимости. Секреты в ADR не включаем.
