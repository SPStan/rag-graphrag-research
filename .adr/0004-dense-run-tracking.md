# 0004 — Экспорт Dense RAG run в MLflow и Langfuse

- Дата: 2026-09-23
- Статус: принято, проверено локально на одном сохранённом вопросе
- Связанные задачи: блок 1.5; ADR-0001 и ADR-0002

## Контекст

Первый реальный локальный Dense RAG запуск уже сохранён в JSONL, но трассировка до этого была проверена только отдельным mock smoke-тестом без модели. Повторный вызов модели ради отправки исторического результата был бы лишним и создал бы новый, несопоставимый эксперимент.

## Варианты

1. Встроить отправку в момент генерации и повторить RAG запуск. Это даст живую трассу, но меняет исполнение и создаёт ещё один результат.
2. Экспортировать завершённые JSONL, метрики и manifest после исполнения. Это сохраняет исходный результат и позволяет связать внешние записи с его `run_id`; время записи trace само по себе не является временем работы стадий.

## Решение

Для текущего локального MVP используем post-hoc экспорт через `scripts/track_dense.py`. Скрипт требует совпадения `run_id`, проверяет hash результатов и корпуса, восстанавливает полные top-k пассажи из зафиксированного корпуса, отправляет параметры, метрики и три файла-артефакта в MLflow, а в MLflow/Langfuse создаёт trace со стадиями query embedding, retrieval и generation. Текст retrieval сохраняется в trace целиком. Экспорт Langfuse ограничен localhost и читает ключи только из `.env`; секреты не печатаются. Счётчики Ollama обозначают локальный usage, а не денежную стоимость внутреннего API.

## Проверка и последствия

Проверен run `06dcabef-de41-4815-a5ac-4bcb3eb01b11`: MLflow run `5ee46c6f61cb43ef9d082f7accfc4676` завершился со статусом FINISHED, содержит метрики и три загруженных артефакта. SHA скачанного JSONL совпал с hash в manifest. MLflow trace `tr-20ee227002d363d48c4ed5333b1c2e0b` и Langfuse trace `f1a4fc02941fa8d6cda110e3187abf78` проверены; оба имеют входы/выходы для retrieval и generation. Langfuse дополнительно подтвердил пять полных пассажей и usage генерации 1178/158 токенов. Первая попытка экспорта оборвалась из-за emoji в кодировке консоли Windows; неполная запись осталась в MLflow со статусом FAILED, повторный запуск завершён. Trace фиксирует содержимое и измеренные значения post-hoc, поэтому длительность самой отправки не равна времени стадии.

Экспорт не меняет JSONL, результат генерации или экспериментальную оценку. Повторная отправка того же JSONL сейчас создаёт новые записи; для повторов следует сначала проверить `run_id` в интерфейсах. Trace и артефакты пережили по одному рестарту Langfuse Compose и MLflow server. Это проверка локального хранения для одного run; результат остаётся PoC, не независимым benchmark.

## Уточнение от 24 сентября 2026: происхождение стоимости dense-кэша

Свежий v5 debug10 run `877f86c6-e9ff-43e1-80f9-d09962e62fe2` экспортирован с общим run_id и проверен в обоих сервисах: MLflow FINISHED, три артефакта и trace; Langfuse trace содержит пять типов observations, 50 passages и usage 15668/1126. Это локальные счётчики Ollama. Предыдущий v5 run и его артефакты повторно проверены после перезагрузки Windows.

Повторный запуск, использующий валидный embedding cache, теперь сохраняет время чтения отдельно от стоимости его построения и включает provenance первоначальной сборки в manifest и оценку. Для MuSiQue no-trunc кэша исторический запуск `ed95bea9-9d11-4234-a80f-46ba3a8fd127` подтверждён как completed, а SHA256 его JSONL совпадает с manifest; исходное построение 5500 embeddings заняло 78,764 с. Локальный sidecar дополнительно фиксирует SHA текущего cache-файла. В историческом manifest отсутствуют embedding token usage и серверные длительности API, поэтому они остаются неизвестными (`null`). Unit test проверяет как успешное восстановление, так и отказ при несовпадающем хэше результата; исследовательские JSONL/manifests не переписываются.
