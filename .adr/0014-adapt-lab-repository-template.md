# ADR-0014: адаптация лабораторного шаблона к существующему репозиторию

Статус: принято для offline-проверок и оформления задач; работу overlay и GitHub Project проверять отдельно.

## Контекст

Руководитель разрешил сохранить существующий `SPStan/rag-graphrag-research`, но попросил привести его к шаблону `Industrial-AI-Research-Lab/nir-project-template`. Репозиторий уже содержит исследовательский код, данные в локальных игнорируемых каталогах, CI и pre-commit. Второй репозиторий студенту не нужен. Шаблон предполагает новый Python-пакет `src/`, `uv`, строгий mypy, issue/PR формы и overlay.

## Варианты

1. Создать новый репозиторий из шаблона и перенести исследование. Это ломает единую историю и противоречит выбору студента.
2. Скопировать шаблон целиком. Пустой `src/` и замена рабочего окружения создадут ложное впечатление проверенного переноса.
3. Вносить применимые требования небольшими PR в существующий репозиторий.

Выбран третий вариант. В этом блоке добавляем `pyproject.toml` и `uv.lock` только для воспроизводимой **offline-проверки**; экспериментальная `.venv` и `requirements.lock.txt` остаются отдельными. `UV_PROJECT_ENVIRONMENT=.venv-check` защищает экспериментальное окружение от `uv sync`. Сохраняем существующий Ruff/pytest маршрут, добавляем mypy лишь для трёх скриптов проверки и хуков, формы issue/PR и CI-конвенции. Это частичное покрытие типов, не подтверждение типизации всего исследования.

Overlay `nir-agent-overlay` и GitHub Project не подключаем молча: сначала проверить их инструкции, права, платформенные детали и согласовать следующий самостоятельный блок. Не создавать фиктивный `src/` и не переписывать результаты экспериментов ради сходства дерева файлов.

## Последствия и проверка

Чистый checkout должен пройти `uv sync --locked` и `uv run --locked python -m scripts.check` на Windows/Linux, pre-commit и Gitleaks. Действующие эксперименты этот check не воспроизводит: интеграционные тесты без локальных данных пропускаются. Изменённые файлы одного PR проверяем относительно `master`; целевой размер — не больше 20 файлов. Решение о расширении mypy, переносе кода в пакет или подключении overlay принимать по отдельному завершённому блоку.
