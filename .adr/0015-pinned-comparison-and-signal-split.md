# ADR-0015: общий протокол и разбиение S500 для сигнала

Статус: принято для планирования issue #7; параметры целевого API и окончательный манифест запусков подтверждаются в issues #8 и #15.

## Контекст

MuSiQue и HotpotQA уже имеют упорядоченные S500 и `pilot200` при seed 42. Локальные raw/manifests показывают выполнение MuSiQue S500[0:100] и S500[200:300]; первый диапазон включает debug10. HotpotQA в доступных локальных журналах не встречается. Отсутствие журнала не доказывает отсутствия просмотра. В `docs/DATA.md` разобран вопрос MuSiQue с ID `2hop__13548_13529` и назван эталон; это позиция 482 прежнего `holdout100`. Модельный запуск на последних 100 в доступных журналах не обнаружен, но весь этот диапазон нельзя называть нетронутым человеком.

## Варианты и решение

Вариант `S500[0:400]` для настройки и старый `holdout100` для проверки отвергнут из-за раскрытого эталона позиции 482. Пересэмплирование всех 500 нарушило бы опубликованные ID и сопоставимость старых запусков. Выбраны неизменные упорядоченные части для обоих наборов:

| Назначение | Позиции S500 | Число | Статус |
|---|---:|---:|---|
| Настройка одного сигнала | 0–299 | 300 | Содержит `pilot200`, debug/baseline и диагностический MuSiQue candidate100; подходит для разработки, не для независимой оценки |
| Однократная проверка выбранного сигнала | 300–399 | 100 | В доступных локальных run ID и точных упоминаниях ID в tracked docs не найдено использования; это ограниченный аудит, не доказательство абсолютной нетронутости |
| Прежний `holdout100`, резерв | 400–499 | 100 | Сохраняется прежний view; MuSiQue позиция 482 документально раскрыта; статус всей группы — не доказан независимый тест |

Файлы `data/ids/*_comparison_split.json` сохраняют ID, исходный SHA, ревизию, seed и назначение. Исходные S500/корпуса не переписываются. Для задачи #21 сигнал, формула, направление и порог выбираются только на 0–299. Эталон для проверки AUROC читается после фиксации сигнала; ни он, ни EM/F1 не входят в вычисление сигнала. Один класс в проверочной части означает неопределённый AUROC без переделки split.

## Следствия и проверка

Резерв последних 100 не исключён из основного описательного сравнения S500. Обнаружение одного раскрытого эталона не означает утечку всех 100 ответов и не доказывает обучение модели на них; выбор нового диапазона — консервативное ограничение для разработки сигнала. На обоих датасетах оставлено одинаковое назначение групп ради простоты протокола. Размер 300/100 относится только к сигналу #21; основной объём 500 вопросов и пилот 200 не сокращены.

Аудитор по умолчанию работает read-only. Неверный/отсутствующий raw-каталог и пустая история не принимаются за доказательство неиспользования; существующие файлы нельзя перезаписать неявно. Исходный `question-usage-audit.json` фиксирует доступную историю до проверки и остаётся неизменным. Явный `--refresh-audit` создаёт или обновляет отдельный `question-usage-audit-current.json`, указывая SHA исходного снимка; он допускает последующие runs на 300–399, но не меняет исходный аудит и разбиение. После запуска исходная проверка нетронутости по текущим raw ожидаемо не проходит, а `--verify-only --splits-only` продолжает проверять границы. CI проверяет опубликованные ID в дополнение к синтетическим тестам.

После новых runs из рабочей папки с локальными `results/raw` запускают `python scripts/freeze_comparison_protocol.py --refresh-audit`. До эксперимента используют `--verify-only`; в чистом checkout без raw — `--verify-only --splits-only`. Исходный аудит также хранит SHA документа с известным раскрытым примером, поэтому его не меняют ради пояснения этой политики.

Полная S500 таблица будет описательной: содержит pilot и исследованные вопросы, включая MuSiQue candidate100. Новые результаты на целевом API можно повторно использовать лишь при совпадении упорядоченных ID, корпуса, модели/версии, генерации, retrieval, reader и оценщика. Проверка сигнала на 300–399 отдельно оценивает выбранное правило; прежний `holdout100` не получает задним числом статус независимой проверки.

`scripts/freeze_comparison_protocol.py` различает planned IDs из manifests и observed IDs из raw JSONL, публикует только позиции/ID, run ID и SHA, не публикует вопросы и ответы. Он отклоняет появление planned/observed run на signal-check диапазоне при исходной проверке до заморозки, но записывает такие runs в последующий аудит. Проверки synthetic fixtures и реальных S500 подтверждают размеры, сохранение `pilot200`, непересечение групп и отсутствие найденных запусков на 300–399 в исходной истории. При новом найденном run, ручном раскрытии gold или изменении цели сигнала решение пересматривается до использования проверки. Полноту личной истории просмотра по локальным файлам подтвердить нельзя.
