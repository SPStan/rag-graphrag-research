# ADR-0017: устойчивый журнал физических попыток

Статус: реализовано offline для существующих локальных Dense/HippoRAG и API smoke; реальный запуск с новым учётом ещё не проверен.

## Контекст и альтернативы

Старые итоговые поля и HippoRAG `usage_events` не сохраняли начало каждого запроса до транспорта; потеря ответа или ошибка проверки могла скрыть расход. Рассматривались HTTP proxy, единая обёртка внешнего `infer` и журнал на точках фактической отправки. Proxy добавил бы отдельный сервис и работу с секретами. Внешний `infer` скрывает SQLite cache и повторы SDK.

## Выбор

Один JSONL журнал `started`/`finished` с fsync и уникальным `attempt_id` используется на реальных транспортных точках. Для HippoRAG LLM обёрнут `chat.completions.create` ниже кэша, а SDK retries отключены; нативный embedding POST записывается отдельно, включая HTTP 400 и его split. Dense и API smoke пишут до POST и сохраняют usage до проверки содержимого. Сводка различает известный subtotal и полный total, повтор чтения и cache hit не увеличивают расход. Manifest закрепляет SHA и run ID; post-hoc экспорт проверяет их, не создавая нового расхода.

## Следствия, проверка и пересмотр

Это технический выбор для измерения стоимости, а не научная новизна. Существующие raw данные не переписываются; отсутствие журнала помечается `legacy_unknown`. Offline fake SDK не доказывает точный физический учёт в живом HippoRAG; первый разрешённый малый запуск должен сверить число запросов, stage/thread context и фактический usage. Пересмотреть решение при изменении SDK, появлении неотключаемых внутренних retry или нового транспорта RAPTOR. В таком случае заблокировать непокрытый путь до инструментирования, а не считать его нулевым.

Корневой Langfuse trace экспортирует проверенную summary и отдельные признаки `complete` и `historical_cache_cost_complete`: валидный SHA не означает полной стоимости. Для HippoRAG commit `1438aba` исходный код передаёт `max_retry_attempts` в OpenAI `max_retries`, а OpenAI SDK документирует `0` как отключение повторов. Runner проверяет оба runtime-значения до модельных вызовов; перед первым малым запуском остаётся проверить установленный SDK с подставным HTTP-транспортом.
