# 0006 — Общий reader для локального сравнения HippoRAG 2

- Дата: 2026-09-25
- Статус: принято для технического debug10
- Связанные записи: [ADR-0003](0003-local-ollama-models.md), [ADR-0005](0005-hipporag2-local-sample.md)

## Контекст

Первый общий прогон Dense/HippoRAG использовал разные reader-подсказки и JSON response mode у HippoRAG. Эти различия не позволяют интерпретировать ответную метрику как сравнение retrieval. Требуется выровнять генерацию, сохранив графовый поиск HippoRAG и общий оценщик.

## Рассмотренные варианты

1. Оставить upstream reader и сравнить метрики напрямую — отклонено: prompt и формат ответа отличаются от Dense.
2. Перевести Dense на upstream HippoRAG reader — отклонено для текущей проверки: Dense v6 уже закреплён, а смена его reader потребовала бы нового базового прогона.
3. Подставить закреплённый MuSiQue v6 template в HippoRAG и использовать общий парсер — выбрано. Общий кодовый тест сравнивает все сообщения reader побайтно по роли и содержимому.

## Решение

Для MuSiQue HippoRAG использует те же system/few-shot/user сообщения, что Dense v6, без JSON режима для QA и с `extract_reader_answer`. OpenIE сохраняет JSON response mode, поскольку он формирует структурированные сущности и тройки. QA-вызовы явно обходят SQLite cache, чтобы debug run подтверждал свежие вызовы модели; исторические результаты и кэш не удаляются. Индексация использует отдельный сохранённый graph state и embeddings, runner записывает новые/повторно использованные записи.

Ollama embedding запросы ограничиваются 18 отдельными входами в секунду даже при внешнем batch. На Windows большой batch не предотвращает исчерпание loopback-портов: [обсуждение Ollama #18392](https://github.com/ollama/ollama/issues/18392) описывает соединение на каждый вход и наблюдавшийся безопасный темп около 18 входов/с. Ограничитель относится к каждому входу и сериализует обращения.

## Проверка и ограничения

Run `a38d6e57-3a33-4ece-aedb-390736ae3a0d` завершён на первых 10 закреплённых MuSiQue ID. Все 10 QA-вызовов были cache miss; модель Qwen2.5 3B Q4_K_M; top-5; `temperature=0`, `seed=42`, `num_predict=512`, `num_ctx=4096`. Общий evaluator дал EM=0,300, token F1=0,380 и recall@5=0,783. Один ответ завершился по лимиту без `Answer:` и корректно получил пустой ответ. Полный набор тестов после правки — 67 тестов.

Это отладочная десятка, использованная при настройке; результаты не являются независимой оценкой и не доказывают превосходство одного метода. Графовый state содержит 5500 passages, 44 890 entities и 48 002 facts; в OpenIE state у 452 passages нет сущностей, у 35 — троек. Два прежних прерванных прохода не сохранили usage, поэтому накопленная цена построения графа неизвестна. Run manifest создан до фиксации изменений и поэтому не содержит Git commit; итоговый код описан этой записью и связанным коммитом. 7B-сравнение и 100-вопросный прогон остаются отложенными.

Пересмотреть протокол после аудита OpenIE покрытия и выбора независимой фиксированной выборки. Не менять prompt, модель, generation options, corpus или top-k внутри парного сравнения.
