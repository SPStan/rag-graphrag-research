# ADR-0018: малый Dense smoke в целевой конфигурации

Статус: протокол принят для issue #10; результаты будут указаны отдельно.

## Контекст и выбор

Issue #10 требует проверить цепочку Dense на пяти development-вопросах каждого набора. Полный S500 и отложенная часть не запускаются. Используем первые пять S500 ID, проверяя их принадлежность `signal_tuning_ids` и исключая `signal_check_ids` и резерв. Корпус содержит объединение всех supporting-пассажей этих вопросов и первые 20 других пассажей закреплённого корпуса; порядок исходного корпуса сохранён. Это корпус для проверки работоспособности, не для оценки качества поиска.

Повторно используем `run_dense.top_k`, нормализацию BGE-M3, reader и parser, журнал issue #9 и `evaluate_dense`. Небольшой orchestrator `run_dense_target` подключает локальный native Ollama embedding и удалённый OpenAI-совместимый HTTP reader. Он не использует HippoRAG/OpenAI SDK; проверка retry того SDK относится к будущему HippoRAG-запуску. Requests проверяется с реальным HTTPAdapter и подставным ответом urllib3, без сетевого подключения.

Для двух наборов используем один неизменённый MuSiQue one-shot reader. Альтернатива создавать новый HotpotQA prompt добавила бы новый фактор: для этого smoke выбираем одинаковый reader и явно раскрываем применение MuSiQue примера к HotpotQA. Формат ответа `Answer:`, cosine top-5, temperature=0, seed=42, output cap=512; reasoning выключается через проверенный `chat_template_kwargs`. Поддержка и фактическое применение параметров backend не выводятся из принятого HTTP-запроса.

Лимит 100 000 токенов на датасет: отдельно сохраняются локальные embedding и remote LLM input/output. До запроса применяется консервативная резервация по размеру UTF-8 JSON + 2048 + output cap, reader input ограничен 16 000 байт. Это оценка для предварительной остановки, не измеренный tokenizer/backend предел. Фактический usage проверяется после каждой попытки; неизвестный расход, превышение лимита, некорректный embedding, неполный ответ или отсутствие `Answer:` прекращают цепочку и запуск следующего набора. Повторов и кэша нет.

## Проверка и последствия

ID, SHA исходных файлов, малого корпуса и queries публикуются без текстов и gold. Raw rows, metrics, manifests и journal остаются локально. Failed manifest перечисляет принятые ID, незавершённые ID и ошибку; usage записывается раньше проверки ответа. Оценщик принимает реальные API-параметры вместо вымышленных Ollama `num_ctx`/`num_predict`.

Протокол проверяется offline-тестами; выполнение и метрики отражаются в безопасной summary. Пересмотреть при смене reader, порядка ID, модели, API-параметров или состава корпуса. Сравнительный вывод по десяти development-вопросам недопустим. Научное согласование и merge предыдущего PR #28 не объявляются состоявшимися; Draft #10 зависит от него и должен быть перебазирован после его слияния.
