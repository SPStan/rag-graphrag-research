# 0005 — Локальная проверка HippoRAG 2 на sample

- Дата проверки: 2026-09-24
- Статус: отдельное окружение и project runner проверены на sample; интеграция с MLflow/Langfuse ещё не выбрана
- Связанные задачи: 2.1–2.2; ADR-0001 и ADR-0003

## Контекст

Нужно проверить, запускается ли HippoRAG 2 на локальных моделях и позволяет ли измерять токены индексации на пассаж. Внутренних API-доступов нет. Основное Python-окружение проекта уже содержит Langfuse и MLflow; добавлять в него тяжёлые несовместимые зависимости нельзя.

## Варианты

1. Установить HippoRAG прямо в основную `.venv`: отвергнут, так как upstream фиксирует собственные версии PyTorch/Transformers и это меняет проверенное окружение.
2. Использовать удалённую модель: недоступно без API-доступа.
3. Проверить закреплённый upstream в отдельном временном venv и обращаться к Ollama через OpenAI-compatible API: выбран для ограниченного sample.

## Проверка и результат

Установлен upstream HippoRAG commit `1438aba3fc44ff10573e5a5e1e7cc3c7f9794aff` (package version `2.0.0a5`) в отдельное окружение Python 3.12.6; `pip check` чистый. Использован официальный `sample`: один вопрос и три пассажа; SHA256 файлов сохранён в [артефакте результата](../results/summary/hipporag2-sample.json). Основная `.venv` не менялась.

Для `qwen2.5:3b` и `bge-m3:latest` указан Ollama endpoint `http://localhost:11434/v1`, OpenIE `response_format={"type":"json_object"}`, размер embedding batch — один объект. Без JSON-режима первый OpenIE запуск не разобрал ответы; с ним построен граф из 30 узлов и 56 рёбер. На retrieval найден supporting passage: recall@5=1.0. Reader ответил неверно, EM=0 и F1=0 на единственном примере; это smoke, не оценка качества.

Usage зафиксирован непосредственно из ответов локального Ollama API. Embedding индексации: 108 токенов для Thomas C. Sudhof, 125 для David Eagleman и 122 для Karl Deisseroth. OpenIE NER+triples: соответственно 883/207, 922/221 и 946/369 prompt/completion токенов на пассаж. Запросы общей фазы отдельно: graph retrieval 2955/81 и QA reader 1089/166. Весь embedding расход этого первого запуска — 1293 токена в 55 запросах, включая сущности, факты и один query embedding; весь chat расход — 6795/1044 токена. Это локальные usage Ollama, не расход внутреннего API.

Повтор с тем же хранилищем подтвердил кэш: 3 passage embeddings, 27 entity embeddings и 24 fact embeddings уже имелись; в OpenIE/индексе не создавались заново. Два повторных chat-вызова обслужены кэшем. Query embedding вычислялся снова (12 токенов). Подробные per-call записи хранились во временной папке и не публикуются; компактные проверенные значения приведены в JSON-артефакте.

## Ограничения и дальнейшее решение

Первый exploratory smoke выше запускался с заменой двоеточия только во временной копии upstream. После него добавлен project runner `scripts/run_hipporag.py`, который задаёт безопасные внутренние метки путей, а исходные имена Ollama-моделей передаёт API. Сам upstream и закреплённый commit не изменены. Зависимость указана в `requirements-hipporag2.txt` и должна ставиться только в отдельное Python 3.12 окружение; основная `.venv` осталась неизменной.

Project runner требует явные пути к корпусу и вопросам, ограничивает запуск 20 вопросами и по умолчанию запускает один. Он сохраняет JSONL, manifest с хешами и per-stage/per-passage usage, вызывает общий evaluator dense reader и отдельно отмечает новые и повторно использованные элементы кэша. Целевые тесты покрывают нормализацию входа, изоляцию меток, учёт usage и обязательность явных путей.

Результат runner сохранён отдельно в [hipporag2-runner-smoke.json](../results/summary/hipporag2-runner-smoke.json). На одном официальном sample граф содержит 25 узлов и 45 рёбер; supporting passage найден на третьем месте (recall@5=1), но ответ неверный (EM/F1=0). Зафиксированы 1132 embedding tokens для построения индекса, 817/192 OpenIE NER и 1897/522 OpenIE triples prompt/completion tokens, 12 токенов query embedding и 1085/184 токена reader. Повторный запуск использовал кэш 3 пассажей, 22 сущностей и 21 факта; QA chat также прочитан из кэша. Runtime context проверен как 4096. Null timings означают, что runner их пока надёжно не измеряет, а не нулевое время.

Это функциональный sample, а не сопоставление качества или затрат с dense. Предыдущий exploratory smoke имел другую конфигурацию и другой граф; числа двух прогонов не являются контролируемым сравнением. Следующий этап — подключить выгрузку завершённых Hippo runs к MLflow/Langfuse и проверить небольшую общую подвыборку при одинаковых вопросах, данных и настройках. Holdout100 не запускался.
