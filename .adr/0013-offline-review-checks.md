# ADR-0013: отдельная offline-проверка для ревью

Дата: 29 сентября 2026. Статус: принято для проверки кода.

## Контекст

Рабочее Windows-окружение содержит MLflow, локальные данные и индексы.
Его успешные тесты сами по себе не доказывают, что репозиторий проверяется
после чистого клонирования. Руководитель требует единый вход проверки.

## Решение и альтернативы

`python -m scripts.check` последовательно запускает pip check, критические
диагностики Ruff и pytest. Make и конфигурация pre-commit вызывают ту же команду.
CI использует отдельный lock зависимостей проверки, Python 3.12, Windows/Linux.
Сетевые соединения тестов запрещены pytest fixture; модельные вызовы не нужны.

Не переносим полный Windows lock в Linux и не обновляем рабочую `.venv` ради CI.
Не выполняем массовое форматирование исследовательского кода: полная style-проверка
остаётся отдельным небольшим изменением. Не создаём собственную замену обещанному
шаблону доски задач и агентским артефактам преподавателя.

## Последствия, проверка, пересмотр

Offline suite проверяет связку на синтетике, а не inference и качество OpenIE.
Integration-тесты без данных/закреплённого HippoRAG имеют явные пропуски.
Критерий приёмки — команда в чистой копии без `.env`, данных и сервисов;
результат фиксируется в VERIFICATION. CI отдельно проверяет две платформы.
При изменении зависимостей тестов пересматриваем отдельный lock и повторяем CI.

Исторические raw-файлы не изменяем: отсутствующую execution revision нельзя
дописать задним числом. Публичный `asbuilt100-code-provenance.json` сохраняет
только записанные source hashes и ограничения. Коммит публикации после запуска
не выдаём за точный снимок исполнявшегося кода.
