# ADR0029: E4 с неполным историческим учётом

Статус: принято для offline реализации issue19; научная карточка требует согласования.

## Контекст

E1/часть запросов имеют неизвестный usage/cache provenance. RAPTOR использовал
Dense leaves. S500 сочетает pilot reuse и новые physical запросы. Прибавление
повторно оплаченного replay или резервов создало бы неверную полную стоимость.

## Решение

Использовать существующую E1 standalone attribution и logical request usage/500
предложенных вопросов как q. Не прибавлять source/development дважды.
LLM input+output и BGE input считать отдельно, исходные поля сохранить.
Привязывать E1 к freeze, E2 к verified E3 SHA/EM; per-case labels не читать.

При неполноте компонента сохранять null и известный минимум отдельно.
Нулевой знаменатель/неположительное пересечение — отдельные случаи.
Сравнение нижних границ не доказывает окупаемость. Допускается одностороннее
доказательство доминирования: один метод измерен полностью и его I/q не выше
нижних границ другого, хотя бы одно строго ниже. C/EM использует EM-долю,
не определено при EM=0; предполагается стационарность качества.

## Альтернативы

Unknown=0, reserve=actual, удаление failed cases и fresh300q при500EM отклонены.
Новые model calls для восстановления учёта вне задачи. LLM+BGE как денежная
цена без тарифов отклонено. Старые raw/plans/frozen manifests не переписываются.

## Последствия и проверка

Полная стоимость графов не идентифицируется. Нижние границы могут исключать
положительную окупаемость. Это не денежная оценка и не безусловный выбор метода:
качество рассматривается отдельно. Mixed extractor/development S500/раскрытие
контроля сохранены. Проверка: synthetic cases, actual offline CLI, source/pin/
accounting checks, byte-identical rebuild и визуальная проверка Matplotlib.
Пересмотр — при доказанно восстановленном учёте или новом согласованном
протоколе/ценовой модели, а не подборе выгодной интерпретации unknown.


## Уточнение по первичному ревью PR41

Пересечение C(N)/EM проверяется независимо от C(N): I и q каждого метода
сначала делятся на его собственную EM. При EM=0 сравнение не определено.
Unknown-флаги после нормировки сохраняются. Регрессия с EM_dense=0.25,
EM_graph=1 показывает, что graph может быть дороже на вопрос и дешевле на
точный ответ. На реальных данных LLM-доминирование Dense проверено заново
после нормировки; неполный embedding-учёт не выдаётся за подтверждённую
окупаемость на точный ответ.
