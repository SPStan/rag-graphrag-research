# 0002 — Зафиксированные данные и идентификаторы пассажей

- Дата: 2026-09-23
- Статус: принято и проверено на двух подвыборках
- Связь: блок 1.2, шаги 1–2 локального MVP, PR #1

## Контекст

Адрес osunlp/HippoRAG_v2 перенаправляется на osunlp/HippoRAG_2. Ревизия при проверке: 5ec05b38deecc3318bb432c69865959c56058990. Скачаны шесть файлов исходного плана; MuSiQue и HotpotQA содержат разные схемы. У MuSiQue supporting-пассажи заданы через paragraphs/paragraph_text, у HotpotQA — через supporting_facts и context. Поля idx непригодны как общие ID: они отсутствуют в части корпусов и могут иметь локальный смысл внутри вопроса.

## Варианты и решение

- Вместо загрузки main при каждом запуске фиксируем ревизию, размер и SHA-256; для обычных Git-файлов дополнительно проверяем blob SHA-1 из HF API. Существующие повреждённые файлы не заменяются молча.
- Сопоставление только по заголовку отвергнуто: у разных пассажей бывают одинаковые заголовки. Используем пару (title, text) после нормализации пробелов. Для HotpotQA проверяем склейку предложений с пробелом и без; ровно один вариант должен совпасть с корпусом. Пропуски и неоднозначности останавливают подготовку.
- ID пассажей — SHA-256 от UTF-8 JSON пары нормализованных title/text. Не используем source idx и усечённые хэши.
- Канонически одинаковые документы объединяются. У MuSiQue 11656 строк дают 11655 уникальных пассажей; у HotpotQA все 9811 уникальны. Текст сохраняется с нормализованными пробелами; это явное преобразование, исходники остаются нетронутыми.
- Из отсортированных ID вопросов выбираем random.Random(42).sample(..., 500). Добавляем все supporting-пассажи, затем случайные дистракторы до 5500. Перемешиваем корпус, чтобы gold-пассажи не стояли первыми. Все входные множества сортируются перед случайным выбором.
- Пилот 200, baseline 100 и debug 10/20 — префиксы того же порядка ID и используют тот же корпус. Это вложенные рабочие наборы, не train/test split для будущего маршрутизатора.
- Вместо передачи исходных вопросников в reader сохраняем отдельно queries.json, labels.json и corpus.json. Правильные ответы, алиасы и supporting IDs доступны только оценке.

## Последствия и проверки

Подвыборки содержат по 500 вопросов и 5500 пассажей: MuSiQue — 882 supporting + 4618 дистракторов, HotpotQA — 996 + 4504. Присутствие всех отмеченных supporting-пассажей проверено; это не утверждение о семантической безошибочности аннотаций источника.

В Git публикуем ID, проверки, манифест источников и агрегированный отчёт без текстов датасетов. Полные исходные и преобразованные файлы игнорируются. Скрипт отказывается перезаписывать ранее зафиксированные результаты иным содержимым; смена протокола требует отдельной версии выходных файлов и нового обоснования.

Тесты проверяют целостность загрузки, реальные подвыборки, воспроизводимость, покрытия supporting, неоднозначность заголовков, вложенность наборов и отсутствие gold-полей в запросах. Сохранённые ID и SHA-256 служат эталоном при переносе окружения. Алгоритм random и версию Python нужно учитывать при переносе; установленный эталон нельзя обновлять только ради прохождения теста.
